Date: 2026-11-01. Baseline af986a8, application 1.3.1. This is an evidence-based technical audit, not a legal opinion or certification. This audit does not itself authorize a release or certify clearance. The owner subsequently explicitly authorized stable publication; unresolved findings remain unchanged.

## Compatibility and redistribution review

1. **PyQt6 6.11.0 — GPL-3.0-only.** The installed distribution declares GPL-only. Riverbank offers GPL or commercial licensing, not LGPL for PyQt. The new original-project GPL license is consistent with that route, but binaries still need GPL notices and corresponding source/build coverage. Prior project's MIT label never excused PyQt obligations. No commercial grant was verified. https://www.riverbankcomputing.com/software/pyqt/ .
2. **Qt 6.11.1 — LGPL v3 wheel / module-specific terms.** Core/Gui/Widgets/Network/Svg/Pdf and TLS/platform/style/image plugins are present. The wheel license is retained; Qt also bundles third-party code (e.g. PDFium, image codecs, FreeType). Source availability, exact source/version/build configuration, module attributions and user's ability to modify/replace applicable LGPL libraries must be verified for standalone and onefile packaging. Do not infer all Qt components' terms from PyQt's license. If relying on GPL options, verify those exact component grants and corresponding-source duties rather than silently assuming blanket GPL coverage. https://doc.qt.io/qt-6/licensing.html .
3. **FFmpeg Gyan 7.1 executable — GPLv3-or-later.** -version confirms --enable-gpl --enable-version3 --enable-static and x264/x265 plus many static dependencies. -L confirms GPL3-or-later. Preserve its separate license and complete exact corresponding source, library sources, patches/configuration and build scripts. General URLs to FFmpeg/Gyan are useful discovery references, not a completed source-distribution offer. No verified exact source archive/valid offer accompanies the old release. This is a **release blocker**. https://ffmpeg.org/legal.html and https://www.gyan.dev/ffmpeg/builds/ .
4. **OpenCV FFmpeg backend — separate LGPL native component.** DLL has LGPL-2.1-or-later libswscale string and a static configuration distinct from imageio FFmpeg. OpenCV wheel's supplied full third-party notice is retained, including its codec/license statements. Exact backend/source/relinking and third-party patent/licensing implications are not independently closed by this audit. OpenCV Apache-2.0 itself is compatible with GPLv3 subject to notices; its wheel includes more than the OpenCV core license.
5. **NumPy 2.2.6 / native BLAS and GCC runtime.** Preserve full installed wheel notice (BSD/OpenBLAS/LAPACK/GCC Runtime Library Exception and other terms). Do not classify every native binary as plain NumPy BSD. Dynamic/import evidence is in the binary inventory.
6. **Pillow 12.3.0, qrcode 8.2, imageio-ffmpeg wrapper 0.6.0, sip 13.12.0, colorama 0.4.6.** Permissive supplier notices are copied. Wrapper BSD does not apply to FFmpeg. Pillow includes vendor notices. No version/library changes are made.
7. **Nuitka 4.1.3 — AGPL compiler + Runtime Library Exception.** The installed supplier files explicitly contain AGPLv3, Runtime Library Exception 1.0 and NOTICE. All are retained. The exception permits independent compiled output under other licenses, so compiler AGPL alone is not evidence that this application's independent original code must switch to AGPL. Confirm runtime file markings/vendor conditions for output; the exception does not cover unrelated models. ordered-set's missing standalone notice remains a build-tool redistribution item; zstandard's notice is copied. No compiler is included as a new application feature.
8. **Python/native Windows libraries.** Python 3.10.6 DLLs/extensions, OpenSSL 1.1.1n, libffi, MSVC runtime 14.x, codecs and compression libraries need their applicable notices/redistribution rights. Python's supplier LICENSE is retained if present. Operating-system/system-library exceptions are not a blanket relicensing of copied DLLs. Not every imported Windows API DLL is actually bundled. No assertion of complete native-license/patent clearance is made.

## Models and assets

## OSM behavior — findings only, unchanged

Unlike the Web implementation, desktop prefetch_for_decoders samples route positions and fetches up to 90 tiles on clip load. The OSM standard tile policy explicitly prohibits prefetch features/bulk downloading beyond active viewing. This is a verified source-level policy conflict, not a hypothetical issue. The memory-only 600-entry cache does not implement HTTP cache-header retention/revalidation or the policy's minimum fallback cache lifetime. The native User-Agent TeslaDashcamStudioPro/1.0 identifies an app but is stale and lacks a contact reference. Existing renderer credit says Map: OpenStreetMap, without contributors/ODbL copyright URL. Legal-page credit does not repair an exported video. Owner review is required before claiming tile-policy compliance. This task changes no endpoint, prefetch, timing, cache, attribution rendering or map behavior. https://operations.osmfoundation.org/policies/tiles/ and https://www.openstreetmap.org/copyright .
