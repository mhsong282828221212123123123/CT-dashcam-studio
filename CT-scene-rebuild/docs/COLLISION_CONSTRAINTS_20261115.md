# 차량 몸체 겹침 검사와 제한 후보정 · 2026-11-15

후속 정정: Aug20 방향 차이는 잘못된 과거 base를 넣은 실행 오류였다. 최신 원인·재검증은 [상대 위치 수정](./RELATIVE_GEOMETRY_EXECUTION_20261115.md) 참조. 아래 기록과 기각 산출물은 당시 이력으로 보존한다.

사용자 요구: 차량은 합쳐질 수 없으므로 충돌 제약이 필요하다. 화면에서 가까워 보이는 것과 월드의 차체 관통을 구분한다. 이번 구현은 후처리 기하 제약이며 충돌 시 튀어나오는 물리 시뮬레이션이 아니다.

## 구현

`src/ct_scene/collision_constraints.py`:

- 실제 로딩한 GLB의 길이·폭과 월드 yaw로 회전 사각형(OBB)을 구성하고 SAT로 관통 깊이를 검사한다. 자차는 렌더러와 같은 -1.2m 차체 중심 오프셋을 사용한다. 고스트도 물리 크기를 가진 대상으로 검사한다.
- 10cm보다 큰 몸체 관통을 시간 구간으로 묶어 검수 FAIL로 기록한다. 단순 접촉과 인접 차로의 정상 통과는 실패가 아니다. 바운딩 사각형은 미러/실루엣을 포함하는 근사이며 실측 충돌 판정이 아니다.
- 렌더링 전에 전체 20Hz 장면 상태를 만든 뒤 양방향 시간 평활화와 겹침 제약을 반복 적용한다. renderer는 이 상태를 그리기만 한다.
- 현재 자동 수정 대상은 동결 선행차를 제외한 측면 추정 위치다. 관측 위치에서 최대 0.75m 안에서만 이동하고 기존 중심 차로를 넘어가지 않는다. 0.75m는 보수적인 정책 상한이며 실측 오차 분포/확률이 아니다.
- 자차·전방 관측·동결 선행차·ID·방향·모델 크기·관측/고스트 여부·도로는 충돌 보정으로 바꾸지 않는다. 같은 위치에 있다는 이유로 차량을 합치거나 지우지 않는다. 근거 없는 앞뒤 순서를 만들지 않는다. 해결할 수 없으면 FAIL을 유지한다.
- 원래 관측 배열은 actors.json에 보존한다. 최종 상태는 render-states.jsonl에 position_before_collision_W/collision_correction_W 및 보정 위치의 support를 남긴다. collision-review.json에는 전후 실패 구간과 변경 내역이 있다. actor-lane-state는 기존 관측 기반 기록이며 수정 좌표로 새 차로를 주장하지 않는다.

`quality_review.py`는 새 영상에 저장된 모델 치수와 자차 pose로 겹침을 독립 재검사한다. 잔여 관통을 일반 수치 검사의 FAIL 항목에 포함한다. 기존 영상에 치수/자차 정보가 없으면 이 항목은 NOT_EVALUATED다. 과거의 PASS를 충돌 검사 통과로 해석하지 않는다.

## 검사 결과

코드 검사 322개 통과. 회전 차체, 접촉, 옆 차로 통과, 자차 중심 오프셋, 수정 상한·차로 제한, 변경 불가 충돌, 중복 위치의 ID 보존을 포함한다.

| 전체 영상 | 프레임 | 겹침 차량쌍·프레임 전→후 | 최종 상태 |
|---|---:|---:|---|
| Oct02 고속 | 1194 | 453 → 286 | FAIL: 잔여 7구간 |
| Aug20 | 1198 | 246 → 240 | FAIL: 잔여 17구간, 별도 방향 회귀로 후보 기각 |
| Oct22 | 1188 | 44 → 44 | FAIL: 변경 불가 겹침 5구간 |

숫자는 겹친 차량쌍·프레임 수이며 고유 영상 프레임 수나 실제 사고 건수가 아니다. 세 전체 영상의 디코딩·원본 시계·마지막 5초 검사는 통과했고 겹침 외 속도/방향 불연속 실패는 없었다. 전체 검수는 위 FAIL을 유지한다. 상세: `runs/collision-constraints-validation-001.json`.

Oct02에서는 기존 actors.json 바이트와 도로가 동일하고 모든 시각의 ID/방향/관측 여부와 카메라 시점이 유지됐다. 수정 위치는 모두 0.75m 이내다. 앞서 복구한 5개 좌측 차량의 선택 직접 관측 구간 존재 검사는 계속 PASS다. `runs/collision-constraints-oct02-source-001/review.json`.

Aug20은 새 합성의 front-0017 방향이 이전 영상과 pi만큼 달라졌음을 발견했다. 충돌 보정 전 관측 배열에서 이미 달라져 있어 이번 위치 제약의 효과로 설명하지 않는다. 원인 규명 전 회귀 통과/합격 영상으로 배포하지 않는다. 따라서 세 영상 모두 기존 방향이 보존됐다는 주장은 하지 않는다.

## 원본 대조와 남은 일

`runs/collision-raw-witnesses-001.jpg`, `runs/collision-front-pair-source-001.jpg`에서 전방 트럭 두 대가 서로 다른 차량이고 원본에서는 분리돼 있음을 확인했다. 현재 추정에서는 일부 구간에서 같은 차로로 몰렸다. 이 문제는 차량을 크게 밀어내는 방식보다 원본에 기반한 차로·거리 추정 수정을 우선한다. 현재 제약만으로 해결되지 않는다.

`runs/collision-constraints-before-after-001.jpg`는 12.05/16초의 후보정 전후다. 남은 관통과 원본 상대 위치를 다음 수정 대상으로 남긴다. 단지 충돌 수가 줄었다는 이유로 위치 정확도를 합격 처리하지 않는다. 기존 먼 차량 누락과 지도/노면 정렬 문제도 별도 미해결이다.

검토용 고속 전체 영상: `runs/collision-constraints-oct02-full-001/surrounding-world.mp4`. 하단 원본 4채널과 Tesla 다크를 유지했다. 테스트26에는 잔여 겹침 FAIL이 명시된 별도 파일로 올리고 이전 결과는 보존한다. Aug20 기각 후보는 올리지 않는다. 최종 Drive ID/파일 크기/부모 확인은 `runs/collision-constraints-delivery-001.json`에 기록한다.
