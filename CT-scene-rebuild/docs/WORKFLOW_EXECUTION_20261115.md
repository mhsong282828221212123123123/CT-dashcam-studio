# 남은 계획 진행 · 30분 작업 · 2026-11-15

## 범위

사용자의 실용 수준 기준을 유지했다. B필러 사각지대 소실, 작은 오차, 먼 차량 미세 ID 문제는 이번 작업의 수정 대상으로 확대하지 않았다. 단계 4의 장면 재사용과 단계 6의 입력 사전 검사·실험실·전달을 진행했다. 기존 코드·영상·실패 기록은 보존했다.

## 구현

1. **추론 전 전체 입력 검사**: telemetry를 먼저 읽고 4채널 packet PTS 범위와 주행 데이터 범위/공백을 검사한다. 실패한 전체 구간을 조용히 잘라 성공시키지 않는다. frame 추출과 모델 실행 이전에 중단한다. packet 검사는 전체 디코딩/노출 동기화 검증을 뜻하지 않는다.
2. **동결 상태 재렌더**: `replay-scene`은 발행된 `render-states.jsonl`의 위치·방향·ID·자차·카메라 상태를 읽는다. 검출·추적·도로 계산을 호출하지 않으며 상태 파일 바이트를 그대로 보존한다. 기존 4채널 strip을 해당 프레임 그대로 가져와 다시 인코딩한다. RGB 무손실 복사나 원본 MP4 신규 sampling이라고 주장하지 않는다.
3. **실험실 화면 설정**: 확대 배율과 도로 밝기를 바꿔 별도 영상을 만든다. 기존 결과는 보존한다. 필요한 ego/model 상태가 없는 이전 결과는 재생/내보내기를 유지하고 새 재렌더 버튼은 비활성화한다.
4. **로컬 OSM 선택**: 지도를 직접 지정하지 않았다면 원본과 같은 이름의 로컬 캐시를 자동 선택할 수 있다. 체크 해제로 끌 수 있다. 새 네트워크 조회나 GPS 차로 배정은 없다.
5. **캐시 계약**: UI·재렌더 전용 코드 변경은 분석 캐시의 코드 fingerprint에서 제외한다. 모델/기하 분석 코드와 입력·backend 변경은 여전히 구분한다. fingerprint 형식이 바뀐 구버전 작업에 대한 자동 migration은 하지 않는다. 이전 완료 결과는 계속 열 수 있다.

## 실행과 검증

- 실제 원본 2개를 새 작업 폴더에서 전 구간 분석했다: Aug25 저속·회전 59.05초/1181프레임(OSM 캐시 사용), Sep02 빈 도로 59.8초/1196프레임(camera-only).

- 정상 원본 3개 입력 사전 검사 PASS. 과거 실패 Aug20 07:30 원본은 우측 영상/주행 데이터 후반 부족으로 거부됐다. 실제 UI CPU 선택·로컬 지도 자동 선택·오류 표시·이전 결과 보존·버튼 복구도 확인했다. 이 CPU 선택 음성 검사는 사전 검사에서 멈췄으므로 CPU 모델 추론 성공을 뜻하지 않는다.
- 동일 버전의 완료 Aug25 작업을 다시 실행했을 때 11개 stage의 cache를 약 1.39초에 검증했고 artifact ID가 모두 동일했다. backend 변경은 거부됐다. 이 검사는 마지막 fingerprint 형식 변경 전에 실행했으며, 새 형식의 UI/분석 경계는 별도 단위 검사로 확인했다.
- 전체 재렌더: 시내 1188프레임 약 23.14초, 고속 확대 변경 1194프레임 약 22.42초. inference 0회, render-state 바이트 동일, 도로 동일. UI 버튼의 전체 replay worker 실행도 통과했다.
- 실제 Qt에서 현재 결과·재렌더 결과·이전 결과의 재생과 허용 버튼 상태를 확인했다. 단순 import 검사만 한 것이 아니다.
- 단위 검사 355 PASS. 잘린 timeline, 중복 ID, 비정상 pose 거부와 renderer가 입력 actor/lamp를 바꾸지 못하는 검사를 포함한다.
- 현재 대표 4개 전체 영상 4759프레임 및 각 마지막 5초 확인. 네 영상의 scene geometry code revision은 동일하다. 두 편은 새 원본 분석, 두 편은 기존 검토본 재사용이며 14개 신규 실행으로 세지 않는다.
- 선택 원본 사건: Sep02 첫 10초 빈 2차로, Aug25 동일 번호판 front→right 연결 및 정차 차량 106표본의 pose 유지 통과. 두 새 base에는 선행 anchor가 없으므로 빈 anchor 검사를 PASS로 세지 않고 NOT_APPLICABLE로 기록했다. 자차는 실제 base 보간과 정확히 같다.
- 실제 Qt 플레이어에서 요약 30초를 끝까지 재생해 유효 프레임 600개와 마지막 29.95초를 확인했다. 재생 오류는 없었다. 이는 실행 검증이며 사람이 영상 전체를 연속 관찰했다는 뜻은 아니다. 기록: `runs/progress-preview-playback-001/review.json`.
- 30초 요약은 저속 20~30초, 고속 18~28초, 교차로 24~34초를 이어 붙인 3개 발췌다. 하나의 연속 주행 30초가 아니다. 모든 segment에 하단 4채널을 유지했다.
