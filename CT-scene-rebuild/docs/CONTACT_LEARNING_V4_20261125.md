# v4 대규모 날짜 확장 및 14×14 FPN 공간 히트맵 CPU 지도학습 결과 · 2026-11-25

## 1. 배경과 데이터셋 확장 (`v4`, 17개 날짜 · 총 213개)

v3에서 5개 학습 날짜·37개 접점만으로는 선형 ridge가 새 날짜 일반화에 실패함을 확인했다. 이에 기존 `G:/3d/CT-scene-rebuild/runs`의 미사용 촬영 날짜 6건(71개 크롭)을 추가로 추출·직접 시각 검수(`visual_reviewed`, `reviewer: Gemini`)하여 17개 날짜·213개 표본의 `configs/contact-learning-annotations-v4.json`을 구성했다.

- **학습 (`train`, 142개 · 11개 날짜)**: 기존 8개 날짜(`oct02`, `2026-10-18`, `aug26`, `aug28`, `oct22`, `aug20`, `2026-11-01`, `oct26`) + 신규 3개 날짜(`aug16`, `aug17`, `sep07`). 유효 접점 **81개**(`front` 30, `left_repeater` 32, `right_repeater` 19), 방향 **138개**.
- **조정 (`validation`, 36개 · 3개 날짜)**: v3 평가에 썼던 `sep02`, `sep08`, `oct21`을 조정으로 편입. 유효 접점 **16개**(`front` 4, `left_repeater` 8, `right_repeater` 4), 방향 **36개**.
- **새 최종 평가 (`test`, 35개 · 미사용 3개 날짜)**: 완전 미사용 날짜 `aug25`, `sep17`, `sep20`(야간 주행 포함). 유효 접점 **22개**(`front` 9, `left_repeater` 8, `right_repeater` 5, 모든 카메라 5개 이상), 방향 **35개**.
- 기존 `v1`, `v2`, `v3` 정답과 모델은 모두 보존했으며, 최종 평가(`aug25·sep17·sep20`)를 본 뒤 재조정하지 않았다.

## 2. v4 모델 구조 (CPU 전용 PyTorch + 단일 ONNX 내보내기)

- **접점 분기 (14×14 FPN Spatial Soft-Argmax)**: 기존 KITTI MobileNetV3-small 백본의 `features[8:]`만 부분 미세조정(CPU, 60 epoch, `AdamW`, CosineAnnealingLR)하고, 14×14 중간 특징과 7×7 상위 특징을 결합한 FPN 히트맵의 soft-argmax로 크롭 내부 정규화 접점 `(u_crop, v_crop)`을 직접 예측한다.
  - 카메라 사전 편향(camera prior)을 제거하기 위해 메타데이터 없이 순수 시각 히트맵으로 위치 이동 등변성(translation equivariance)을 확보했다.
  - 학습 증강: 좌우 반전(`u→1-u`), 랜덤 크롭/이동 지터, 밝기·대비·채도 지터, 차량 높이 단위 Smooth-L1 손실. 추론 시 좌우 반전 TTA 적용.
- **방향 분기 (고정 KITTI 백본 + Ridge + Flip-TTA)**: 접점 미세조정이 KITTI 사전학습 방향 특징을 덮어쓰지 않도록 방향 분기는 원본 고정 백본(`AvgPool2d(4, stride=3)`) + 정규화 Ridge + 좌우 반전 TTA로 분리했다.
- 두 분기를 단일 CPU ONNX(`models/contact-adapter-v4/contact-encoder.onnx`)로 내보냈으며 CUDA나 외부 다운로드는 사용하지 않았다.

## 3. 성적 및 판정

접점 오차는 검출 상자 높이로 정규화한 이미지 2D 거리이며 미터 오차가 아니다.

| 분할 | 접점 수 | 상자 바닥점 평균 / 중앙값 / p90 | v4 모델 평균 / 중앙값 / p90 | 방향 정확도 (다수결 기준) |
|---|---:|---|---|---|
| 학습 (`train`, 11개 날짜) | 81 | 0.1746 / 0.1335 / 0.4299 | 0.0605 / 0.0541 / 0.1103 | 137/138 (99.3% vs 36.2%) |
| 조정 (`validation`, `sep02·sep08·oct21`) | 16 | 0.1883 / 0.1492 / 0.4032 | **0.1380 / 0.1085 / 0.2952** (-26.7%) | 22/36 (61.1% vs 30.6%) |
| **새 최종 평가 (`aug25·sep17·sep20`, 야간 포함)** | **22** | **0.1754 / 0.1405 / 0.4710** | **0.1618 / 0.1001 / 0.3850** | **23/35 (65.7% vs 20.0%)** |

### 판정: 전 지표 개선 확인, 단 엄격 기준 미달로 기본 3D 미적용 유지 (`runtime_adopted=false`)

- **분명한 진전**:
  - v2(`oct26` 평균 +63.2% 악화) · v3(`sep02·sep08·oct21` 평균 +0.7% 악화, 방향 44.4%)와 달리, v4는 **야간 주행이 포함된 미사용 3개 날짜(`aug25·sep17·sep20`) 전체 지표에서 상자 바닥점 기준선을 일관되게 앞섰다**: 평균 **-7.7%**, 중앙값 **-28.8%**, 최악 오차(p90) **-18.3%**, 방향 정확도 **65.7%(다수결 20.0% 대비 +45.7%p)**.
  - v3에서 실패했던 `sep02·sep08·oct21`에서도 평균 접점 오차가 `0.1896 → 0.1380`(-27.2%)로 대폭 개선됐다.
- **미승인 사유**:
  - 엄격한 2D 후보 기준(`mean < 0.9 * baseline` = -10% 이상 개선)에 근소하게 못 미쳤고(-7.7%), 방향 정확도(65.7%)도 70% 기준에 2표본 부족하다.
  - 또한 2D 이미지 접점·4방향만으로 실제 3D 거리·중심·월드 요(yaw) 정확도가 입증되지 않으므로 `models/contact-adapter-v4`는 `runtime_adopted=false`, `applied=false`, `metric_position_available=false` 상태로 보존한다.
