# 첫 접점·방향 가중치 학습 · 2026-11-25

## 결과와 적용 여부

실제 별도 가중치를 학습했다. 기존 KITTI 차량 MobileNetV3 특징 추출부는 고정하고 새 접점 보정·방향 출력 가중치를 학습했다. 전체 신경망을 재학습한 것은 아니다. 학습과 ONNX 실행 모두 CPU이며 CUDA를 사용하지 않았다.

**기본 장면에는 미적용.** 접점의 최종 날짜 평가에서 평균 이미지 오차가 20.4% 줄었지만 조정용 날짜에서는 5.3% 나빠졌고, 방향은 다른 날짜에서 13/19(68.4%)에 그쳤다. 오른쪽 카메라의 최종 접점 평가도 2개뿐이다. 차량 3D 중심·거리·월드 방향의 정확도는 검증하지 않았다. 이번 가중치를 적용해 기존 3D 결과가 개선됐다고 보고하지 않는다.

접점 선택 결과는 image feature strength=0이다. 즉 이번 작은 자료에서는 시각 특징으로 새 접점을 찾는 모델보다 카메라·상자 위치/크기에 의한 보정이 선택됐다. 방향 쪽은 고정 시각 특징을 사용했다. 이 차이를 숨겨 '차량 위치 신경망 재학습 성공'으로 부르지 않는다.

## 자료

- 원본 6개 영상에서 직접 검토한 차량 크롭61개. 바퀴가 가려졌거나 불명확한 25개 접점은 null로 두고 접점 손실에서 제외했다.
- 라벨은 Codex가 원본 이미지로 검토한 잠정 라벨이다. 사용자가 검수한 인간 정답이나 실측이 아니다. 표시 크롭에서 약8픽셀의 접점 불확실성을 기록했다.
- 학습: Oct02, Oct18 교차로·램프 29개(접점17개). Oct18 두 클립은 같은 촬영 세션으로 묶었다.
- 조정: Aug20 12개(접점5개). 최종 평가: Nov01 고속·도심 20개(접점14개). Nov01 두 클립도 같은 날짜의 최종 평가로 묶었다.
- 기존 월드 XYZ, 차로 배정, OSM, 기존 차량 진행방향은 학습 정답에 사용하지 않았다. 입력은 원본 이미지 특징과 카메라/상자 메타데이터다.
- 방향 정답은 이미지에서 보이는 차체 전방의 대략적인 네 방향(멀어짐·다가옴·왼쪽·오른쪽)이다. 영상 내 운동 방향이나 정밀 3D yaw 정답이 아니다.
- 접점은 보이는 바퀴의 지면 접촉점 중간이다. 이를 차량 3D 중심으로 곧바로 대체하면 안 된다.

## 검증 수치

오차는 차량 검출 상자 높이로 정규화한 이미지상의 2D 접점 거리다. 실제 미터 오차가 아니다.

| 자료 | 접점 수 | 기존 상자 바닥점 평균 오차 | 학습 보정 평균 오차 | 방향 정확도 |
|---|---:|---:|---:|---:|
| 학습 |17|0.1699|0.1390|28/28|
| 조정 |5|0.1522|0.1602|6/12|
| 최종 평가 |14|0.1646|0.1311|13/19|

최종 평가의 접점 p90은0.3923→0.3064다. 단일 날짜·표본 부족·잠정 라벨 불확실성이 있어 일반화 성공 근거로 삼지 않는다. 학습 정확도100%와 별도 날짜68.4%의 차이가 과적합 위험을 보여준다. 최종 평가를 보고 파라미터를 다시 조정하지 않았다.

## 실행·보관

- `models/contact-adapter-v1/`: 실제 가중치 adapter.npz(약100KB), CPU 특징 추출 contact-encoder.onnx(약3.7MB), manifest.json, training-report.json. 기존 약121MB 원본 모델 전체를 복사하지 않고 필요한 고정 특징 부분만 보관했다. 원래 모델 출처와 해시를 기록했다.
- `configs/contact-learning-annotations-v1.json`: 61개 라벨·원본 이미지 해시·촬영 세션·분할·가림 상태·검토 주체.
- `src/ct_scene/contact_learning.py`: 날짜/원본 이미지 누출 차단, 접점 표적 변환, 새 출력 가중치 학습 계산.
- `src/ct_scene/learned_contact.py`: CPU 전용 실험 예측. 반환값 applied=false, metric_position_available=false. 기존 장면이나 차량 좌표를 수정하지 않는다.
- 준비 `tools/prepare_contact_learning.py`, CPU 특징 추출 `tools/extract_contact_features.py`, 학습 `tools/train_contact_adapter.py`, 독립 CPU 검토 `tools/review_contact_adapter.py`.
- 학습 의존성은 기존 .orientation-export-venv의 PyTorch CPU를 사용했다. 추론 검토는 기존 .venv의 ONNX Runtime CPU를 쓴다.

원본 크롭은 `runs/contact-learning-labels-003`, 특징은 `runs/contact-learning-features-002`, 첫 학습은 `runs/contact-learning-trained-001`, 실행 검토는 `runs/contact-learning-review-001`이다. 준비001의 일반 메타데이터 판별 오류와 특징001의 ONNX pooling 내보내기 실패도 덮어쓰지 않았다. 002에서 같은 풀링을 지원 연산으로 내보내 성공했다.

코드425검사 PASS. 날짜/원본 이미지 누출 거부, 가려진 접점 손실 제외, 상수 특징 안정성, CPU 입력 형식을 확인했다. 실제61개 전체의 PyTorch/ONNX 특징 최대 차이7.4e-6, 패키지 접점·방향 예측 일치 PASS. 이 검사는 모델 정확도 판정과 별개다.

[30초 검증 영상](https://drive.google.com/file/d/1Je_kRwyXjw0WV4LbUYwGf8UXBFyirCwB/view?usp=drivesdk)은 최종 평가20개의 **정지 원본 프레임**을1.5초씩 보여주는 접점·방향 검토 자료다. 하단4채널을 포함하며 새 3D 재현이나 추적 개선 영상이 아니다. 빨강은 기존 상자 바닥점, 파랑은 학습 후보, 초록은 잠정 이미지 라벨이다. 600프레임 전체 디코드, 테스트26 업로드 후 크기·부모 폴더 확인.

## 후속 기준

이번 가중치는 성공으로 승격하지 않는다. 다음 실험에서는 바퀴·가림 상태별 원본 라벨을 늘리고 사람이 구분 가능한 차체 랜드마크를 사용해야 한다. 같은 평가 세트를 반복 조정에 쓰면 더 이상 최종 평가로 부를 수 없으므로 새 촬영 세션을 따로 남긴다. 이미지 접점 개선 이후에 카메라별 재투영·동일 차량 연결을 검증하고, 지원되는 거리 기준을 확보한 구간에서만 3D 위치 보정을 학습한다. 기본 화면 적용은 별도 날짜의 접점·방향과 실제 월드 연속성 검증 후 결정한다.
