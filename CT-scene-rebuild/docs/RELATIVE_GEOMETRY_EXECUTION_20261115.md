# 차량 상대 위치 수정 실행 · 2026-11-15

계획의 첫 항목인 겹침 원인 수정부터 수행했다. 충돌만 보고 차를 크게 밀어내는 방식 대신 거리 계산 전환, 약한 관측의 차로 중앙 보정, 측면 도색 정렬과 가림을 수정했다. 전체 계획 완료나 상용 품질 합격 판정은 아니다.

## 수정 내용

1. **전방 거리 전환**: 지면 추정이 70m를 넘었다는 이유로 무관한 높이 기반 거리로 전환하던 조건을 제거했다. 명확하고 잘리지 않은 직접 관측은 같은 지면 모델로 140m까지 처리한다. 예산 초과를 다른 거리 모델을 쓰는 근거로 사용하지 않는다. 기존 확정 선행차 앵커는 유지한다. 멀리 있는 지면 추정은 실측값이 아니며 관측 도로 범위를 넘을 수 있다.
2. **약한 차로 보정**: 작은/불명확한 박스에서 관측 가중치가 낮다는 이유로 임의 차로 중앙 prior를 강하게 적용하던 조건을 수정했다. 명확한 관측이나 독립적인 측면 도색 근거가 없으면 중앙으로 당기지 않는다.
3. **차종 분류**: 먼 작은 박스의 다수결이 후반의 명확한 차체 관측을 덮지 않도록 했다. 큰 관측 중 반복된 고신뢰 클래스가 일치하면 우선한다. 좌측 0010의 승용차 오분류를 트럭으로 수정했다. 체형 분류는 휴리스틱이며 전체 차종 정확도 주장이 아니다.
4. **측면 도색 정렬**: 차량 박스를 마스킹한 흰 도색에서 근거리/다음 도색을 찾고 전방 카메라 기반 기존 차로 경계에 맞춰 측면 지면 좌우 축을 조건부 정렬한다. 자차 궤적, 도로, OSM 차로 수를 조절하지 않는다. 앞 2/3 시간으로 맞춘 뒤 뒤 1/3의 도색 오차로 거부할 수 있게 했다. 차량 위치는 카메라 정렬 계수를 맞추는 데 사용하지 않는다.
5. **가려진 접촉점**: 앞차가 트럭 바퀴를 가리면 bbox 하단을 실제 접지점으로 믿지 않는다. 반복된 같은 영상의 가림 관계, 앞차의 도색 기반 차로, 경계 부근 불확실성이 함께 확인될 때만 차로 후보를 보완한다. 강한 가림의 짧은 구간은 안정된 관측의 종방향 운동과 기존 차로로 최대 4초 보완하고 그 근거를 기록한다. 역방향/과속/잔차 초과/긴 공백은 거부한다. 이는 추론이며 새 직접 지면 측정으로 표시하지 않는다.
6. **충돌 후보정 거부**: 비동결 전방의 작은 지면 추정에는 관측 시선 방향 안에서 최대 2m 깊이 수정만 허용한다. 측면은 기존 0.75m 상한이다. 충돌 수를 줄이더라도 새 속도 불연속을 만드는 보정은 해당 시간 구간에서 거부한다. ID/방향/차체 크기를 충돌 때문에 바꾸지 않는다.
7. **기준 입력 검증**: 장면이 사용한 frozen base ID와 실제 재합성 base ID가 다르면 합성 전에 중단한다. 의도적으로 다른 기준을 쓰려면 별도 `--allow-base-change`가 필요하다.

주요 파일: `surrounding.py`, `lane_prior_geometry.py`, `side_paint_geometry.py`, `collision_constraints.py`, `tools/render_rebased_case.py`, `tools/review_guards.py`. 기존 코드/원본/실패 후보는 보존했다.

## 원본 검수의 정정

`left_repeater-0019`를 이전에 첫 차로로 집계한 것은 잘못됐다. 35.2076초 원본 흰 경계선과 차량 위치는 **두 번째 차로**다. 0010 트럭도 그 뒤의 두 번째 차로다. 증거: `runs/side-lane-independent-review-003.jpg`. 이전의 5개 첫 차로 검사 PASS 중 0019 판정은 무효이며 이전 파일을 덮어쓰지 않았다. 정정 이력: `runs/relative-geometry-annotation-correction-005.json`.

현재 source 검사는 4개 첫 차로 차량과 2개 두 번째 차로 차량의 선정된 구간이다. 누락됐던 승용차와 트럭의 차로, 모델 종류, 관측 구간의 존재/solid를 확인해 6개 모두 PASS다. `runs/relative-geometry-oct02-source-005/review.json`. 영상 전체 검출률/모든 차량 ID/실측 거리 합격이라는 뜻은 아니다.

Aug20의 180도 방향 차이는 비결정성으로 확인된 것이 아니다. 이전 회귀 실행에서 수정된 `correction-body-phase-base-001` 대신 과거 `yellow-gauge` base를 넣은 **실행 입력 실수**였다. 올바른 기준으로 다시 실행했으며 이번 base ID 차단이 잘못된 입력을 실제로 거부하고 출력 폴더도 만들지 않음을 검사했다. 과거 기각 기록은 유지한다.

## 최종 engine005 검증

동결 코드: `runs/relative-geometry-engine-005`. 코드 검사 333개 PASS. 세 영상 모두 같은 코드이며 기존 확정 앵커 위치·방향은 각각 187/180/26표본 그대로다. 입력 ID, 디코딩, 전체 원본 시계와 마지막 5초를 검사했다.

Oct02의 직전 전달본은 기하 수정 전 453, 제약 후 286건이었다. 이번에는 기하 수정 자체로 56건, 제한 후보정 후 10건이다. 모두 **겹침 차량쌍·프레임 수**이며 사고 건수/고유 프레임 수가 아니다. 이전 286개 겹침 표본 모두에서 두 차량이 새 상태에도 존재한다. 차량 삭제로 얻은 감소가 아니다. 자차 카메라 시점도 동일하다. `runs/relative-geometry-pair-retention-005.json`.

최종 10건은 34.15초 1프레임(0.207m 관통)과 40.95–41.35초 두 전방 트럭의 9프레임이다. 후자는 원본 bbox가 겹치고 가림이 발생하는 구간이며 3D 상태에서는 아직 합당하게 분리하지 못했다. 강제 깊이 보정 후보가 새 속도 불연속을 만들어 기각됐음을 collision-review에 남겼다. 41초에 실제 두 트럭이 동일 차량이라고 확인하거나 ID를 합친 것이 아니다. 겹침 외 수치 불연속은 최종 세 영상에서 없었다. 상세: `runs/relative-geometry-validation-005.json`.

Oct02 좌측 정렬 계수는 scale 1.08935, offset -1.37422m다. 뒤 시간 구간 도색 오차 중앙값 0.218m, p90 0.632m이며 차량 위치 실측 오차가 아니다. 같은 개발 영상 안의 시간 분리 검사이므로 새로운 독립 holdout 성공으로 부르지 않는다. 우측과 다른 두 영상의 도색 정렬은 근거 부족으로 거부했다.

주유소/반대편 차량을 차로에 강제로 넣지 않는 기존 선택 검사와 정상 우측 handoff는 PASS다. Oct22 반대편 Mercedes 제외도 유지됐다. Aug26 음성 대조는 기존 노면004 결과를 재사용했다. `runs/relative-geometry-outside-source-005/review.json`.

**추가 source 실패**: Aug20 59초의 front-0080은 새 지면 거리로 관측 도로 끝을 넘어 차로 unknown이다. 앞/solid는 유지하지만 원래의 ‘한 차로 오른쪽’ 검사를 통과하지 못한다. 도로 범위를 임의로 늘리거나 이 FAIL을 PASS로 재분류하지 않았다. `runs/relative-geometry-yellow-source-005/review.json`. 원래 Hyundai/Carnival 상대 차로 실패도 해결됐다고 주장하지 않는다.

## 남은 계획

겹침 원인 수정과 측면 paint 기반 정렬, 짧은 가림 후처리 일부를 진행했다. 다음은 전방 가림/접촉점과 ID 대응의 남은 불확실성, 다른 영상의 잔여 상대 위치/차로 실패다. 장면 동결과 렌더러 완전 분리, 전체 14구간 재검수/새 holdout/편집기 확인, 도로 말단·교차로의 남은 정렬, 낮은 우선순위의 사람/폴은 아직 완료하지 않았다. 이번 3개 영상을 14개 전체 동일 엔진 검수로 보고하지 않는다. CUDA·빌드·릴리즈·푸시는 하지 않았다.

## 사용자 검토 결과

사용자가 “이정도면 일단 합격”이라고 평가했다. 현재 Oct02 수정본을 잠정 합격 비교 기준으로 보존한다. 잔여 겹침 2구간 및 다른 영상의 source 실패, 자동 검사 FAIL은 원래 기록 그대로 유지한다. 영상·동결 엔진·게시된 artifact는 수정하지 않았다. 전체 계획 완료로 기록하지 않는다.
