# 좌측 포켓차로: 형태를 인식하는 구현안

아래는 최초 구현안이다. 후속으로 형태 인식·local 렌더·차량 배치를 1차 구현했고 `LEFT_POCKET_IMPLEMENTATION.md`에 실제 검수와 남은 한계를 정리했다. 모든 포켓의 일반 검증이 완료된 것은 아니다. 화면은 1.3배 확대를 유지한다.

## 현재 놓치는 이유

`road_evidence()`는 여러 프레임의 paint를 대부분 횡좌표 histogram으로 합치고 도로를 일정한 `boundaries_y`로 만든다. 따라서 중앙선과 분리선 사이 간격이 진행 위치에 따라 변하는 테이퍼가 사라진다. 이후 `lane_count>=3`이며 좌측 lane 0에 actor가 없다는 조건으로 `inferred_empty_turn_pocket`을 부여하고 임의의 종료를 적용하는 임시 규칙은 실제 분기 검출이 아니다. 정지선 후보도 포켓 시작/끝 검출을 대신하지 못한다.

## 판단 근거와 구현 순서

1. 전방 및 좌측 리피터에서 중앙선/분리대 쪽 경계와 백색 분리선을 관측한다. 차·반사·차체는 가리고, paint 표본의 진행 위치와 원본 frame ID를 보존한다. 전체 구간의 한 median으로 축약하지 않는다. 화면 가까운 약 5–40m를 먼저 다루며 이는 현 추정 광학의 작업 범위이지 실측 거리 보장이 아니다.
2. 본선 분리선이 계속 이어지는 동안 그 바깥 경계가 벌어지는지 확인한다. 본선 구간과 포켓 구간의 횡방향 폭을 진행 거리별로 분리한다. 모든 선이 나란히 휘거나 이동하면 곡선/도로 이동 후보이며 새 차로가 아니다.
3. `pocket_width(s)`를 도입한다. 시작에서는 0, 테이퍼에서 점차 증가, 포켓 구간에서 유지하고 교차로/합류 근거가 있는 곳에서 종료한다. 같은 폭의 차로를 전체 구간에 한 줄 더 붙이지 않는다. 약 한 차로 폭은 prior일 뿐 고정 폭으로 먼저 맞추지 않는다.
4. 좌회전 화살표·정지선·그 공간을 사용하는 차량의 궤적은 포켓의 용도와 존재를 보강한다. 차량이 없어도 두 경계의 분기와 지속이 확인되면 포켓을 그린다. 반대로 단일 차량이나 빈 공간 하나만으로 포켓을 생성하지 않는다. 불명확한 용도는 '좌측 추가 차로 후보'로 남긴다.
5. 후처리로 같은 도로 위치를 나중에 더 가까이/다른 camera에서 본 관측을 모아, 가려졌던 시작부의 모양을 되돌아가 수정한다. 복원한 구간에는 근거 frame과 추정 상태를 남긴다. 자차 좌표나 본선 lane ID를 포켓에 맞춰 이동/재번호화하지 않는다.
6. 기하 근거가 확보되면 현재의 '빈 lane 0 = 포켓' 규칙을 대체한다. 렌더는 테이퍼를 가진 local road strip을 그리고, 차로 상태도 진행 위치별 유효 경계를 사용한다. OSM은 교차로 위치·연결 형태의 참고로만 사용하며 GPS로 자차 차로를 지정하지 않는다.

## 검수 기준

- 빈 포켓 / 차량에 가린 포켓 / 포켓 없는 본선·완만한 곡선을 별도 원본 사례로 검수한다.
- 시작/넓어짐/유지/교차로 종료가 원본과 같은 순서여야 한다. 본선을 곧게 펴거나 자차를 움직여 겉으로 맞추지 않는다.
- 자차가 차로를 바꿔도 포켓의 world 위치와 본선 ID는 유지돼야 한다.
- 검출 수나 unit test 통과를 인식 성공으로 부르지 않는다. 전방·좌측 원본과 같은 시각의 3D를 비교하고, 잘못 생긴 차로/포켓이면 다시 수정한다.
- 조명·차량 가림 때문에 분리선을 확정할 수 없는 구간은 추정으로 구분한다. 포켓 기능 완료 판정은 실제 positive와 negative 원본 검수 후에 한다.

이는 새로 드러난 곡선/pose-to-road 문제와 연결된 local road geometry 작업이다. 건물/정밀 rig 보정이나 무거운 신규 신경망을 선행 필수로 늘리지 않고 paint topology부터 구현한다.
